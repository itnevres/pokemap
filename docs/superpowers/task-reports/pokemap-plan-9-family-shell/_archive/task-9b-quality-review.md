Verdict: Approved with changes (C0 / I2 / m5). Constraints hold: fitWithBand reused, shortcutGuard shared, reactStrictMode used, no new deps, listeners cleaned up.

## Important
I1. `fitContext` is duplicated near-verbatim in WorldCanvas.tsx and GbcWorldCanvas.tsx (same fitWithBand args, same worldViewFromMapView call; only `native`, the placement variable and the setter differ). `useWorldContext` already receives native, placement, viewport, world.setView and context.origin, so a `worldContext.fit()` (or `fitContext`) there would hold the single copy and make `fit = inContext ? worldContext.fit : fitX` trivial. The "composite = placement*native + 2*origin" assumption (symmetric border ring) is now stated in two places and would have to be changed in both. Duplication is acceptable only if the plan chose it; otherwise share.
I2. The context-fit composite size is re-derived (`w*native + 2*origin.x`) rather than taken from what MapCanvas's own `fit` uses (`pixelWidth`). If the border is ever asymmetric (or MapCanvas pixelWidth includes something else) the in-context Fit silently diverges from the Map view Fit that the title/test claim to match. The tests only cover the symmetric case and use the same formula as the oracle (see m3). Prefer reusing the real composite size, or comment the assumption.

## Minor
m1. Magic values `bandNative: 0, side: "left"`: side is irrelevant at band 0, but unexplained. Add a one-line comment, or default them in fitWithBand. The `viewport.w || <composite w>` fallback is copied from MapCanvas (`|| pixelWidth`) so it is consistent, but it is also uncommented and duplicated again.
m2. WorldCanvas passes no `native` to worldViewFromMapView (relies on default 16) while useWorldContext gets `native: 16` and the Gbc twin passes BLOCK_PX. Pass `TILE_PX` explicitly.
m3. Tests hard-code geometry that mirrors the implementation: `10 * 16 + 2 * 16`, `10 * 32 + 2 * 32`, viewport `400/100`, `200/200`, and `levels: [1, 2, 4]` instead of ZOOM_LEVELS. Using fitWithBand as the oracle is right, but the origin/size literals will drift silently from the fixtures; derive them from the fixture constants. The `lastDraw().slice(5, 7)` index magic in MapCanvas.test is opaque (name it).
m4. Copied tests: the WorldCanvas and GbcWorldCanvas "F does what the Fit button does" bodies copy the existing Fit-button test wholesale (fixture + assertion). An `it.each(["click","key"])` over one body would remove the copy and prove equivalence directly. The Gbc test "Fit all fits every placement..." keeps a stale name after the rename to "Fit"; GbcMapCanvas F test omits the pan assertion the GBA twin has.
m5. `fitEnabled` is true when in-context with origin loaded but `contextPlacement`/`contextSize` still null (GBA); the button is enabled and F is consumed (preventDefault) but fitContext no-ops. Fold those into the enabled flag. In GBC, fitContext sets the view without `fitted: true` (fitAll does); harmless in context but inconsistent. `useFitShortcut` assigns `latest.current` during render (common pattern, fine here; an effect-assignment is the stricter form).
