## Findings

1. **Moderate — rename unexpectedly resets Dungeon pan and zoom.** `packages/ui/src/gbc/GbcApp.tsx`, anchor `const mapFilter = useMemo(() => openDungeon ? new Set(openDungeon.maps) : null, [openDungeon]);`; `packages/ui/src/gbc/GbcWorldCanvas.tsx`, anchor `fittedFilterRef.current === mapFilter`. The GBC dungeon hook reloads the full list after every successful PATCH. Renaming replaces `openDungeon` with a new object even though its `maps` have not changed, so `mapFilter` becomes a new Set and the canvas's filter effect calls `computeFit` again. A user who has panned/zoomed to inspect a dungeon loses that view after a rename. Preserve the filter identity when the membership has the same names, or compare member contents before refitting. Add a test that pans/zooms, renames, and observes unchanged view while membership changes still refit.

2. **Minor — a long warp failure can expand the World toolbar beyond its canvas.** `packages/ui/src/gbc/GbcWorldCanvas.tsx`, anchor `{warpError && <div className="world-canvas__toolbar-group"><span className="world-canvas__toolbar-error"`. `fetchGuarded` includes up to 200 received characters in an unexpected-shape error. This new flex group lacks `min-width: 0`, while `.world-canvas__toolbar-error` uses `white-space: nowrap`. The existing CSS grants `min-width: 0` only to `world-canvas__toolbar-group--save-error`; the new generic group keeps its long min-content width, so its ellipsis cannot constrain the toolbar. Reuse the save-error modifier or give this group the same shrink rule, then exercise a long malformed response at a narrow viewport.
