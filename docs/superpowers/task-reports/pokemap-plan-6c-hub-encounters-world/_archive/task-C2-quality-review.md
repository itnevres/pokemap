## Checked, no finding
- **Effect deps `[selected]`**: reads only refs + `document`; no stale-closure risk; `eslint exhaustive-deps` clean (refs). Data reload / `worldMode` / `visibility` change: no re-scroll (intended; same-`selected` test pins it with new-equal `data`).
- **Rapid selection changes**: each commit re-runs the effect on the then-current `aria-current` row; `scrollIntoView` default behaviour not smooth (no `scroll-behavior` in `styles.css`), so no animation pile-up.
- **Ancestor scrolling**: scroller is `.app__sidebar` (`overflow-y:auto`, `styles.css`); `html/body/#root/.app` are `height:100%`, `.app__body` `min-height:0`, so the page/shell is not scrollable; `block:"nearest"` (inline defaults nearest) moves only the sidebar. No sticky/scroll-margin rules to fight. Side effect: a tree click on a partly clipped row nudges it fully into view -- fine.
- **Same map in two groups**: `querySelector` returns the first `aria-current` row; both rows get `aria-current`. Groups are disjoint by construction (React `key={m}` per group, GBA/GBC group data), so theoretical only.
- **`details.open = true` vs React**: `open` prop is constant `true`; React diffs prev/next props, never rewrites the attribute, so the imperative open survives re-renders; filter hiding/showing a group re-mounts it with `open` (pre-existing). Native `toggle` event fires, React doesn't listen. Focus is never moved (spec), so AT gets no announcement of the expansion or of the `aria-current` change from a world click; acceptable since the click originated in the canvas, not the tree. A user who collapsed a group and then world-clicks inside it gets it re-opened (intended).
- **Filter-focus guard**: in real browsers `mousedown` on the canvas blurs the filter input (non-focusable target -> activeElement=body), so the guard rarely blocks a world click; implementer's "no scroll when filter focused" note applies mainly to programmatic/keyboard cases.

Setters called side by side, none inside an updater. `selectMapFromWorld` is re-created every render and `onCanvasClick` is a plain per-render function, so `selected` is never stale at handler time; two same-tick clicks both go through the guard (harmless). Re-click of selected map skips confirm (pinned). Dirty session follows `selected` in every mode, so guard from world click is required and present.
