## Blocking findings

1. **P1 — GBC coordinate grounding is false.** “GBC warp coords and world placements use blocks” mixes units. `load/events.ts`, anchor `outOfBoundsEventDefects`, states events are 16-pixel steps; `toWarp` preserves raw x/y. World placements and dimensions use 32-pixel blocks. Require an explicit adapter conversion, including how half-block coordinates and integer placement rounding work. Measured AzaleaTown warp 7 is raw `(2,10)`, hence block position `(1,5)` before any explicitly chosen center offset; its dimensions are 20×9 blocks. The current false premise can choose the wrong edge. The gate's third event really targets `AZALEA_TOWN, 7`, so the 1-based destination claim is sound.

2. **P1 — Zero overlaps conflicts with fixed-anchor preservation.** Read-only `buildWorld` measurement finds ten overlapping pairs among the 179 shown maps in multi-map GBA components, including Route29/Route30, AzaleaTown/Route34, and Route42/EcruteakCity. D2 says never alter these anchors, while acceptance requires zero overlaps for both corpora. The plan's literal all-placement assertion cannot hold under U1. Pin the pre-existing overlap set and require zero newly introduced overlaps, explicitly record this grounding correction, and retain the exact-zero GBC assertion where feasible. Also reconcile “hidden maps are not blockers” with “all placements”: hidden shelf maps can occupy new shown positions even if the rendered view is clean. State the collision population precisely. Manual overrides may intentionally overlap; test automatic geometry separately.

3. **P1 — The third GBA example is unreachable under the specified traversal.** The stated dimensions/warp destinations for all three examples match source. However, BFS forward from every multi-map GBA component reaches GraniteCave_1F and MeteorFalls_1F_1R but neither SeafloorCavern_Entrance nor Room1. Entrance is itself a singleton, not an initial anchor. Underwater_Route128 warps to Underwater_SeafloorCavern; entering the cavern involves an emerge connection omitted by a warp-only traversal. Thus the spec simultaneously mandates a shelf fallback and adjacency to an unplaced anchor. Pick a measured reachable third dungeon, or explicitly resolve traversal semantics with the parent plan before implementation; do not silently manufacture reverse warps or dive edges.

## Required specification clarifications

4. **P2 — Collision-search order is internally ambiguous.** A square spiral uses Chebyshev shells; Manhattan-distance-first search uses diamond shells. N/E/S/W only orders the four cardinal points, leaving diagonal ties undefined. Pin one total candidate order and a complete blocked fixture with exact coordinates. The current blocked fixture has no dimensions/obstacles/expected result, so it is not yet an executed acceptance pin.

5. **P2 — Determinism and fallback need one precise contract.** Existing `autoLayoutUnplaced` iterates unsorted input-derived clusters and height-sort ties, so preserving its shelf coordinates while requiring arbitrary input-order invariance is not generally possible. GBC cannot call this GBA-Project-specific helper unchanged. Its `buildGbcWorld` already shelf-packs all components before returning; singleton positions do not remain seed origins as the fact list implies. Name each family's fallback and decide whether input-order invariance applies only to the pure helper with fixed placements or to rebuilt worlds as well.

6. **P2 — Mutation witnesses are incomplete.** Hidden-chain and overlap mutants can change output with suitable fixtures, but these must assert exact placements. Reversing traversal on independent targets can be equivalent, and a deterministic reverse sort passes repeat/reversal equality. Use two competing anchors or targets whose preferred rectangles collide, pin the canonical winner, and prove the mutant changes that output before adopting its ID. Removing the actual canonical sort against permuted input is an appropriate nondeterminism mutant.
