## Behavior

Add a family-agnostic helper over map-name keyed baseline placements, shown/hidden names, normalized warp links (both endpoints where resolvable plus source ordinal), map sizes, and gap. It returns new placements and never mutates input. GBA uses `autoLayoutUnplaced` shelf positions as fallback when enabled. GBC uses singleton positions from immutable `buildGbcWorld` as fallback; it has no auto-layout toggle, so near-warp always applies to shown singletons and existing `?dungeons=0` ignored behavior stays unchanged. GBA's `dungeonAutoLayout` and per-request `?dungeons=0` remain authoritative. Manual sidecar placements apply last in both families.

For each unresolved shown singleton, BFS **forward from that singleton toward a currently placed shown map** over directed source warp links. Traverse hidden maps, but do not traverse through a different shown singleton that is not yet placed; this lets floors place outward one level at a time. A usable path must end at a currently placed shown map on an edge whose destination endpoint resolves. An edge with unresolved endpoint may continue through a hidden map but cannot be the final anchor edge. Use the resolved arrival endpoint on that shown anchor as the geometry point (the last source warp may belong to a hidden intermediary and has coordinates in that intermediary's frame). This clarifies Plan 6c's “source warp on the anchor” wording: the final edge's resolved destination warp is the anchor-frame endpoint; the intermediate source coordinate cannot be used as if it were in the anchor frame. Each iteration gathers candidates with such paths, sorts by shortest path length, then candidate map name, then full edge-key sequence `(fromMap, sourceOrdinal, toMap, destinationWarpOrdinal-or--1)`, places the first candidate, and adds it to the shown anchor set. Recompute until no candidate is reachable; remaining maps keep their family's fallback position. This deterministically places 1F before B1F when B1F's directed path leads to 1F. Do not add planar connection, dive, or emerge edges.

Convert the resolved arrival endpoint into family world units before adding the anchor origin. Pick the nearest anchor edge by Manhattan distance to its half-open rectangle; ties use north, east, south, west. Place the target outside that edge with the configured gap and center-align it against the endpoint. Round its top-left to the nearest integer, with half ties toward positive infinity (matching `Math.round`). Never alter a multi-map anchor. First classify graph-reachable shown singletons; obstacles are positive-size shown automatic placements only: fixed multi-map anchors, shown unreachable fallbacks, and already-placed near-warp targets. Hidden maps do not block; manual placements apply afterward and may overlap. If preferred position is blocked, enumerate integer offsets at Manhattan radii 1,2,…; within each radius visit N/E/S/W cardinal offsets first, then all remaining offsets by ascending y then ascending x. Pin an exact blocked fixture and first free point. Finite obstacles and finite rings guarantee termination.

If no reachable shown anchor exists, retain the existing shelf position. Existing manual placements apply last and continue to override all automatic placements.
