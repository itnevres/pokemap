## Re-measured implementation facts

- `autoLayoutUnplaced(proj, world, opts)` in `packages/core/src/world/warpGraph.ts` takes a GBA `Project`, `World`, and enabled/gap/origin options. It returns placements only for singleton planar components, unioned by warp connectivity and shelf-packed. It uses each source map's forward warp events and resolves destination ids through `idToName`.
- GBA `/api/world` builds a base `World`, feeds `proj.map(name).warpEvents` plus a map-id lookup into the normalized adapter, passes the result through `resolveWorldPlacements`, and serializes the resolved positions. `?dungeons=0` still removes singleton placements as before; when enabled, near-warp replaces shelf coordinates and shelf output is only the unreachable fallback.
- GBC `/api/world` keeps the existing base-world cache, builds its event adapter from `loadGbcMapEvents`, clones placements into the resolver, applies near-warp to shown singletons, then serializes via `buildGbcWorldPayload`. Every request's resolver output is fresh; the cached base world remains byte/value identical.
- `resolveWorldPlacements` starts from every `buildWorld` placement, replaces singleton positions with automatic output when enabled, deletes singleton placements when disabled, then applies sidecar manual placements last.
- `buildGbcWorld` returns placements for all 391 maps and shelf-packs its components. It has exactly three multi-map planar components; singleton fallback positions are from this immutable baseline, not component-origin seeds and not GBA's shelf output.
- GBA `Conflict`: `{map, viaA:{from,x,y}, viaB:{from,x,y}}`; GBC re-exports the same shape. Recheck types before review.
- GBA warp `destWarpId` is a zero-based index into the destination's `warpEvents` array; the measured subject values are parseable and non-negative. `ShoalCave_LowTideEntranceRoom` → `Route125` id `0` resolves to Route125 warp 0 at (22,19). The adapter resolves each arrival event and retains both endpoints and source event ordinal.
- GBA examples: `GraniteCave_1F` (42×15) forward-reaches shown `Route106`; `MeteorFalls_1F_1R` (30×42) forward-reaches shown `Route114`; `ShoalCave_LowTideEntranceRoom` (35×35) directly warps to shown `Route125` at source (20,30), destination warp id `0`. - `GbcMap` does not expose warp events. Its route adapter calls `loadGbcMapEvents(proj.root, map)`, resolves `mapConst` through `GbcMap.constName`, preserves source ordinal, and resolves positive 1-based `destWarp` to the destination map's event. `destWarp === -1` has no fixed destination and is omitted from geometric links. ## Behavior

Add a family-agnostic helper over map-name keyed baseline placements, shown/hidden names, normalized warp links (both endpoints plus source ordinal), map sizes, and gap. It returns new placements and never mutates input. GBA uses `autoLayoutUnplaced` shelf positions as fallback when enabled. GBC uses singleton positions from immutable `buildGbcWorld` as fallback; it has no auto-layout toggle, so near-warp always applies to shown singletons and existing `?dungeons=0` ignored behavior stays unchanged. GBA's `dungeonAutoLayout` and per-request `?dungeons=0` remain authoritative. Manual sidecar placements apply last in both families.

For each shown singleton planar component, search forward from that singleton along directed source warp events until reaching a currently placed shown map. Resolve each edge's destination event; when a path reaches the anchor, use the arrival endpoint on that shown anchor as the geometry point. The last source warp may belong to a hidden intermediary, so its coordinate is not the anchor point. Traverse hidden maps without placing them. Place candidates by increasing shortest-path length from initially placed shown multi-map anchors; ties sort by map name, then edge key `(fromMap, sourceOrdinal, toMap, destinationWarpOrdinal)`. For multiple equal-length paths choose the lexicographically smallest complete edge-key sequence. A placed shown singleton becomes an anchor for later searches. Do not add planar connection, dive, or emerge edges. Unreachable maps keep their family's fallback position.

Convert the resolved arrival endpoint into family world units before adding the anchor origin. Pick the nearest anchor edge by Manhattan distance to its half-open rectangle; ties use north, east, south, west. Place the target outside that edge with the configured gap and center-align it against the endpoint. Round its top-left to the nearest integer, half ties toward the lower integer. Never alter a multi-map anchor. Obstacles are positive-size shown automatic placements only: fixed multi-map anchors, shown unreachable fallbacks, and already-placed near-warp targets. Hidden maps do not block; manual placements apply afterward and may overlap. If preferred position is blocked, enumerate integer offsets at Manhattan radii 1,2,…; within each radius visit N/E/S/W cardinal offsets first, then all remaining offsets by ascending y then ascending x. Pin an exact blocked fixture and first free point. Finite obstacles and finite rings guarantee termination.

If no reachable shown anchor exists, retain the existing shelf position. Existing manual placements apply last and continue to override all automatic placements.
