## Independent specification review

**Finding — Important:** `packages/server/src/blockEditRoutes.ts:83`, `:179`, and `:261` reject every cell request whenever the effective grid has fewer than `width * height` blocks. B14d specifies the 409 `BAD_GRID` response for a requested cell inside the declared dimensions whose index is beyond the available grid data. For example, a 4×4 grid with 15 blocks currently rejects `(0, 0)` even though block 0 exists. Narrow the condition to the requested cell index being outside the effective grid, retaining the mandated path, count, and dimensions in the error. This affects both GBA and GBC.

The staged-grid choice matches the planner in both families: the alphabetically first open map sharing the grid file wins, with disk used otherwise. The cap calculation considers canonical metatile-file aliases and both layout roles using the existing `gbaConsumingLayouts` helper; the behavior and layer validation checks safe integers and upper bounds before bitwise masking; and the enum/define layer options implement the specified numeric forms and fallback. No core helper was exported or changed. These are static review observations; the requested runtime verification was not independently run.
