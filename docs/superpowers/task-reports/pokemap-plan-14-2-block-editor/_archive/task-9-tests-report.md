## Numbered coverage

All buffer/path/id/count expectations are built by the tests from disk reads and their own constructions; no expectation is read from the code under test. Both families run against temp copies only (GBA: `copyGbaTilesetProject` + `removeGbaTemp`; GBC: `copyGbcSubjectToTemp` + `removeTemp`), with both corpus suites behind `describe.skipIf(!hasProject(SUBJECT_ROOT))` / `describe.skipIf(!hasGbcProject(GBC_SUBJECT_ROOT))`.

The shared metatiles file is found by scanning each project — GBA: group maps by the canonical `metatilesBin` of their layout's primary and secondary tilesets, pair with the same role (secondary additionally requires the same `splitFor(...).metatiles`), prefer a secondary pair (it exercises the O8 split offset), else a primary pair (offset 0); GBC: group maps by `metatilesPath`. A pair that does not exist fails loudly: `expect(found, "two maps sharing a metatiles file").toBeDefined()`.

Brief case 1 → test: "refuses another map's stage while one map owns the file (NOT_OWNER, O2)". A stages an append (16 opaque bytes); B's `stageTilesetPlan` on the same file throws `BlockEditRefusal` with code `NOT_OWNER` and the O2 message **exactly** (see interpretation 1). B's session, blocks/border/map/events, `canUndo`/`canRedo`/`isDirty` and `snapshotOf`/`gbcSnapshotOf` output are all compared before and after the refusal.

Brief case 2 → "keeps ownership through an edit that restores the baseline (O1), releases on undo". A stages an append, then stages the inverse (`after` = disk baseline). B is still refused `NOT_OWNER` (ownership follows history, not bytes). A undoes twice (the routes, 200/200) and then B stages successfully.

Brief case 3 → "keeps ownership through a partial undo; full undo releases it". A stages edit 1 (append) and edit 2 (one flipped byte of the staged output). B is refused; A undoes once → still refused; A undoes the other → released, B stages.

Brief case 4 → "refuses redo with NOT_OWNER while another map owns the file; a redo after the owner discards succeeds". A stages; A undoes; B stages. A's redo route answers **409** with `code: "NOT_OWNER"` and `error` starting with `<mapA>: <path>: <mapB> has unsaved` (interpretation 4). `canUndo`/`canRedo`, blocks and `tilesetEdits` are unchanged; after B discards, a second redo succeeds (200) and A's `tilesetEdits` holds one entry.

Brief case 5 → "refuses redo with FILE_CHANGED after the other map committed; history is unchanged". A stages; A undoes; B stages, then B **plans and commits through the real routes** (`GET plan` → `refusals: []`, `fingerprint` truthy → `POST commit` → 200, after which the file on disk must equal `before + NEW_METATILE` byte-for-byte). A's redo answers **409** with `code: "FILE_CHANGED"` and `error` containing the path; A's `canUndo`/`canRedo`, blocks and `tilesetEdits` are unchanged. The two written files are restored in `finally`.

Brief case 6 → "leaves the owner's tileset files on disk byte-identical when the other map saves". A staged the append; B paints a normal cell (pencil 1×1, id `0` or `1` — whichever differs from the cell's current block; always a real block below every saved count) and commits through plan/commit. A's metatiles bytes are byte-compared before/after; A still owns (B's subsequent stage → `NOT_OWNER`). Files restored in `finally`.

Brief case 7 → "refuses paint of the appended id with pencil, rect and bucket (UNSAVED_BLOCK); shift and lower ids are fine" plus a direct `refuseUnsavedBlockRefs` boundary test. Each of B's `paint/apply` calls with the new map-visible id answers **409** with `code: "UNSAVED_BLOCK"` and `error` containing A's name; B's blocks are unchanged after each refusal. A painting its own new id → 200; an id below the saved count → 200; `shift` (no ids) → 200. For GBA the new id is `split.metatiles + savedCount` for a secondary-half pair (O8: map-visible → file-local by the half the shared file belongs to) or `savedCount` for a primary pair (offset 0); for GBC map-visible == file-local.

Brief case 8 → "a discarded append leaves no session referencing the id, and releases ownership". A stages, then A discards (200). `store.has(A)` is false, no remaining session's blocks reference the appended id, and B then stages successfully.

Brief case 9 → "one stageTilesetPlan with a placement is one undo step covering tileset and grid". One `stageTilesetPlan` call with `placement { x: 1, y: 1, blockId }` is one undo step: one undo restores both `tilesetEdits` (`[]`) and the grid cell; one redo re-applies both. GBA placement ids are clamped to `0x3ff` (the grid's 10-bit mask), GBC to `0xff`.

Brief case 10 → "snapshotOf / gbcSnapshotOf include `tilesetEdits` (`[]` when absent)". Both families assert `snapshot.tilesetEdits` equals `[]` for an absent field and equals the staged array when set. The `Snapshot`/`GbcSnapshot` types gained the optional field (types only); `snapshotOf`/`gbcSnapshotOf` still populate nothing, so this case is red by design until Task 9 implements the population.

Brief case 11 → "ownedTilesetPaths returns the session's paths, restored entries included" and "never refuses the caller's own paths; paths are checked in sorted order", plus the `refuseUnsavedBlockRefs` boundary test. `ownedTilesetPaths` must return both a changed and a restored (`after === before`) entry's path for one session and an empty set for a fresh session. `requireTilesetOwnership` with two owned paths and two owners, caller not an owner: the thrown `NOT_OWNER` names the **alphabetically first** path and its owner; calling with the caller's own path skipped still names the foreign path; pure own-path calls pass. The entries are iterated from `store.entries()` in insertion order and the paths are passed unsorted (`[path2, path1]`), so an implementation that checks paths in request order names `path2` and fails.

## Interpretations

1. **O2 (case 1, exact message).** The ruling file is unreadable; the plan's Task 9 interface list quotes `"<path>: <owner> has unsaved block edits to this file; save, undo or discard them there first"`. Case 1 asserts `refusal.message` with exactly this string, naming the shared path and map A. If the real O2 text differs, both families fail at that one assertion — flagged for the conductor to reconcile with the file. Quote: plan, Task 9 interfaces, `requireTilesetOwnership` row.
2. **O1 (case 2).** Ownership follows history, not bytes — an edit followed by its inverse keeps the file owned until the last change touching it is undone (then released), saved or discarded. Quote: plan ("ownership follows history, not bytes: edit → inverse edit keeps it") and spec, "Session ownership, Save and undo" ("Ownership lasts while any staged change to that file remains in the owner's history … released by Save, Discard, or undoing the last change that touched the file").
3. **O7 (paint guard).** The exact message text is **not in the worktree** and the ruling file is unreadable; the plan says only "`UNSAVED_BLOCK` naming the owner". The tests pin only: HTTP 409, `body.code === "UNSAVED_BLOCK"`, `error` containing the owner's map name, and B's blocks unchanged. The message itself is not asserted. Same for the direct boundary test, which pins code + owner name and nothing more.
4. **Redo body (case 4).** The brief shows `{ error: "<A>: <path>: <B> has unsaved ...", code: "NOT_OWNER" }`. Read as: the route prefixes the requesting map's name to the core refusal message → asserted as `error.startsWith(\`${mapA}: ${path}: ${mapB} has unsaved\`)` and `code === "NOT_OWNER"`. An `eventFailure`-style body (`${map}: ${sourcePath}: …`) does **not** match this assertion, and a bare core message does not either; the error line to change is `expect(redo.body.error.startsWith(...))` marked in the test. If the rulings define a different wrapper, only that one line changes.
5. **FILE_CHANGED (case 5).** Reuses core's existing refusal (`checkTilesetBaselines` → `BlockEditRefusal("FILE_CHANGED", "<path>: changed on disk since the block edit was staged")`). Asserted: 409 + `code === "FILE_CHANGED"` + `error` contains the path. The wrapper text is not pinned beyond the containment check. B's commit closes B's session (as both commit routes do today), so B owns nothing at A's redo and the baseline check is what fires — this is why FILE_CHANGED rather than NOT_OWNER.
6. **History unchanged (cases 4, 5).** Defined as before/after equality of `canUndo`, `canRedo`, `blocks` and `tilesetEdits` across the refused redo — not deep equality of the whole session (monotonic cleanIndex/isDirty updates would make a full-session compare flaky).
7. **Case 5 vs 4 — baseline vs ownership ordering.** The redo path is expected to run `requireTilesetOwnership` and then `checkTilesetBaselines` on the target snapshot's paths (plan, Task 9: "Redo: before restoring, requireTilesetOwnership and checkTilesetBaselines for every path in the target snapshot; on refusal, history and bytes unchanged"). Both cases would also discriminate a validator that only checks one of the two.
8. **Case 6 "B paints a normal cell"** — the cell is painted with id `0` (or `1`, whichever differs from the cell's current block). That is a real block, guaranteed to differ, and below every real saved count; a role-dependent id formula was rejected because it could collide with the current block in the secondary half. B's paint goes through `paint/begin` → `paint/apply` → `paint/end`, then the real plan/commit routes with the plan's fingerprint. Disk byte-compare of the owner's file before/after; ownership re-checked by B's stage afterwards.
9. **Case 7 / O8.** The scan prefers a SECONDARY pair (role and split identical for both maps, enforced at scan time); the map-visible id of the appended block is `split.metatiles + savedCount`; for a secondary-half pair an implementation that ignores the split (paints `split + count` as file-local without subtracting) is caught by the "below the saved count paints fine" sub-case, which must succeed for the correct offset and refuses for the naive one. A PRIMARY pair (offset 0) is the documented fallback; the test names which it found only through the id arithmetic it derives. For GBC there is no split and map-visible == file-local.
10. **Case 9 (placement).** `placement.blockId` is clamped to the grid's mask for the write to be representable (`0x3ff` GBA, `0xff` GBC). Placement semantics beyond the single cell (collision/elevation kept) are not asserted — they are Task 6/7 planner scope; the oracle pins only the one-undo-step-covering-tileset-and-grid behaviour.
11. **SessionPayload.** The stub's exported `SessionPayload` shape is my design: `blocks`, GBA-only `border?`/`map?`, GBC-only `events?`, `isDirty`, `canUndo`, `canRedo` and `tilesetEdits: TilesetFileEdit[]` (the merged staged edits). No test inspects a returned payload's fields — payload consumers are Task 10/11 and this oracle pins the merged effect through the session instead; over-asserting the payload shape now would just duplicate Task 11's own contract tests. Flagged to the conductor in case the rulings fix a different SessionPayload shape.
12. **ownedTilesetPaths "undo side of its history"** (plan interface, not the brief's case 11). Not tested here: the undo side of `EditCommandStack` is not introspectable through the public API and the snapshot commands would need to carry the staged paths — nothing at this hop can construct that state without the implementation. The brief's case 11 pins only the session paths and restored entries, which is what is tested. The plan's history clause is documented on the stub for the implementer.
13. **Case 8 assertions.** (a) the discard route answers 200 and closes the session (`store.has(A) === false`), (b) no remaining session's blocks reference the appended id, (c) ownership is released — B stages successfully afterwards. "No session references the id" is checked by scanning every open session's `blocks` (the only id-bearing surface); restored-element comparison is not meaningful because A's session is gone.
14. **BlockEditPlan.** Core does not export it yet (Tasks 6–7 are in fix round); the stub declares it with exactly the plan's Task 6 contract fields (`edits`, `newBlockId?`, `placement?`, `warnings`, `usage`, `confirm`, `revision`). Replace the declaration with an import from core when Task 6 lands (`types.ts` or `gbcOps.ts`).
15. **Snapshot types.** `Snapshot.tilesetEdits?: TilesetFileEdit[]` and `GbcSnapshot.tilesetEdits?` added as optional fields only; `snapshotOf`/`gbcSnapshotOf` are untouched, so case 10 is red by design. The comment on each field points at Task 9 for the population.
15a. **Session `tilesetEdits` access (fix round).** The plan puts `tilesetEdits?: TilesetFileEdit[]` on `EditSession`/`GbcEditSession` themselves ("Session field on both `EditSession` and `GbcEditSession`"), but the core types this worktree compiles against (`node_modules/@pokemap/core`) are a stale copy lacking that field — hence the 34 TS2339 errors. Since only the session stores and the test may change here, the test pokes the field through `editsOf`/`setEditsOf` narrow casts to `{ tilesetEdits?: TilesetFileEdit[] }`. At runtime the extra property round-trips unchanged (same pattern as the 14.1 suite's hand-set `session.newNames`), and case 10 stays red-by-design (`snapshotOf` does not populate the field yet). Once Task 9 lands core's `tilesetEdits`, the casts become no-ops and can be replaced with direct property access in the implementation hop.
16. **commit fingerprint flows.** Cases 5 and 6 commit through the real `plan` → `commit` round trip with the real `fingerprint` from the plan body; `refusals: []` and a truthy fingerprint are asserted before the commit, so a planner bug fails loudly instead of mis-reading a 400 as a red test for the wrong reason.
17. **Temp-copy hygiene.** Cases 5 and 6 write the shared metatiles file and B's grid; both are byte-snapshotted and restored in `finally`. No other case writes disk. GBA grid restore covers `layouts/.../map.bin` (shared or not), GBC covers `<map>.blk`.
18. **Restored-entry ownership (case 11).** Sessions' `tilesetEdits` are set by hand via `setEditsOf` (the 14.1 suite's `session.newNames = []` pattern, adapted to the stale-core types — see 15a), since `stageTilesetPlan` is the stub; the restored entry uses `before === after` bytes with a fresh baseline Buffer.
19. **Red-by-design map.** With the stubs: cases 1–9 fail at the first `stageTilesetPlan` call; case 10 fails at `toEqual([])` (snapshot lacks the field at runtime); cases 11–13 fail at `ownedTilesetPaths`'s non-`Set` throw / `requireTilesetOwnership`'s non-`BlockEditRefusal` throw / `refuseUnsavedBlockRefs`'s non-`BlockEditRefusal` throw. Every failure points at the missing implementation, not at a test bug.
20. **Windows placeholders.** `NEW_METATILE = Buffer.alloc(16, 0x5a)`; flipByte masks a single byte; all `.replace(/\\/g, "/")` normalizations mirror the add-event suites. No test hardcodes a map name; the A/B pair always comes from the scan.
