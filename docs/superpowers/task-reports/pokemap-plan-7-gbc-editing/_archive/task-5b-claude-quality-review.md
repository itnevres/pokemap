### Observations that are not findings

- Sequential queue: a pencil drag now sends one cell per round trip. On a slow link the queue can trail the cursor, and a map change or unmount drops the not-yet-sent cells of that stroke. By design (B1), tested, and better than the old parallel POSTs, but worth knowing.
- The `!ownsStroke(stroke) && !stroke.begun` branch in `endActiveStroke` (GbcMapCanvas.tsx ~712) is only reachable when retirement happens between queueing the end and running it, because `strokeRef` is nulled on retirement. Correct, just subtle.
- A commit in context leaves the user in context (Done must be pressed again). This mirrors the GBA App and its comment.

## Things I specifically checked and found sound

- **Stale closures in stroke serialization.** `endActiveStroke` runs from the mouseup render's closure, so it ends the stroke on the CURRENT session, while the retirement cleanup uses the `end` captured at mousedown (`stroke.end = editSession.endStroke`). That split is right: `useGbcEditSession.post` closes over `mapName`, so the captured one posts to the OLD map's URL, and the hook's response guard (`latest.current.mapName === mapName`) drops its state update. Retirement never sends an end to the new map.
- **Double endStroke.** `endActiveStroke` nulls `strokeRef`, so the unmount/map-change cleanup does not enqueue a second end. `strokeOpenRef` is false after mouseleave, so a later mouseup is a no-op. I found no path to two ends for one stroke.
- **Leaked server strokes.** Begin issued but unresolved when the visit retires: begin resolves, `begun = true`, the cleanup's queued end then runs. Begin not yet issued (behind a previous end): the begin step sees `!ownsStroke` and returns, and the cleanup sees `begun === false`, so nothing is sent for a stroke the server never saw. Matches the tests "map/ABA/unmount retires pending begin/apply".
- **Unhandled rejections.** Every assigned chain ends in a `.catch`; the retirement chain's `.catch(() => {})` is deliberate. The only way to poison the chain is M3.
- **Errors for a retired visit.** `ownsStroke(stroke)` gates all failure sites; `canvasVisitRef` is replaced on every `mapName` change and on unmount. `GbcMapEditing.isCurrent()` is a second, independent guard at the host.
- **GbcMapEditing render-time reset.** Terminates after one extra render (`visit.mapName === mapName` afterwards). `isCurrent` compares the closure's `visit` object with the committed one, so A -> B -> A produces a distinct object and old callbacks stay dead. StrictMode's effect double-run (null, then reassign, in the layout effect) is harmless. No render loop.
- **GbcWorldCanvas overlay.** The Escape listener is added/removed on `[inContext]` and reads handlers through refs, so it cannot go stale or leak. The capture-phase ordering reasoning holds (the context menu closes on its own window listener but `menuOpenRef` is set during render; SaveDialog and the warp modal both carry `aria-modal="true"`). The snap effect is ref-guarded against StrictMode re-runs and gates the overlay canvas until snapped. Fit all is disabled in context and the key handler consumes +/- while the payload is pending. The World canvas is not remounted: the `false` placeholders in GbcMapEditing's fragment and in GbcApp's host div keep child positions stable, and the tests assert node identity.
- **tileVersions.** Only the bumped map's cache entry is dropped; a stale in-flight load lands on the detached entry. A remount with an existing version requests `&v=n` on first load.
- **Windows junction safety (world.test.ts).** `afterAll` unlinks each junction before `rmSync`. If `unlinkSync` throws, the throw propagates out of `finally` before `rmSync` runs, so the recursive delete is never reached with a live junction. If a junction dangles, `existsSync` is false, but then there is nothing behind it to delete, and Node 24 (v24.13.0 here) treats a junction as a link in `rmSync`. The prefix check on `tmpdir()` guards the root. Same pattern as the pre-existing scratch block. After my run no `pokemap-world-gba-*` or `pokemap-d4-gba-*` directories were left in the temp dir.
- **Real GBA corpus writes (world.test.ts).** I found no write to `C:/Programming Projects/Pokemon Game/game` from this file: sidecar paths all go through `projectPaths(fixtureRoot)` / `projectPaths(scratch)`, and the four data directories are only read through junctions. The real `.pokemap/world.json` mtime (Oct 10) did not change across my run. The modified tracked files in that corpus (NavelRock*, layouts.json) have August mtimes, so they are the user's own edits, not test residue.
- **Test quality.** Async assertions are consistent: `await act(async ...)` in React 18 drains the microtask queue through a macrotask before resolving, so the synchronous follow-up expects in the held-promise tests are deterministic, not timing-based. No fake timers in the new tests. Each `waitFor` targets one concrete condition. Reading each negative test against the code it guards (retired-visit failure x begin/apply/end, ABA stale ops x 6 operations x success/failure, capture-phase Escape, input/textarea/select exclusion, cancelled-confirm never mounting the overlay via a MutationObserver), each would fail if its guard were removed. The exception is M1.
