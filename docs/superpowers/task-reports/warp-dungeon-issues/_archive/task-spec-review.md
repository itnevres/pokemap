## Mandatory findings

1. **P1 — pending non-paint edits can escape the popup guard (both families).** `packages/ui/src/App.tsx:123-126` and `packages/ui/src/gbc/GbcApp.tsx:160-163` gate close only on `popupBusyRef`, populated exclusively by canvas paint callbacks. Event drag/inspector move/add/delete, undo/redo and discard do not set it (`useMapEditing.ts:115-200`, `MapEditingWorkspace.tsx:80-81`, `GbcMapEditing.tsx:115-142,168-169`). Repro sequence: open a clean destination; issue a delayed event move; press X/Escape before its response. Local isDirty is still false, so popup closes. A further map selection can switch the App-owned session before completion; GBA applies the old response into the new selected session, while GBC drops its local response but leaves the old server session dirty. Pending discard also permits close/reopen or new mutations before it finishes. Protect all session mutations used by the popup until completion, and surface their failures. Verify a deferred event move and deferred discard, not only paint.

2. **P1 — busy boolean clears between adjacent canvas strokes while the later stroke is pending.** In `packages/ui/src/components/MapCanvas.tsx:748-759,833-861`, a new mousedown starts begin immediately, replacing the pending chain; each prior end's finally clears busy unconditionally. A disabled fieldset does not disable canvas pointer handlers. Stroke 2 can start while stroke 1 end is delayed; stroke 1 then clears busy and permits close/save before stroke 2 finishes. GBA also sends mousemove applies directly rather than behind begin/prior applies (`783-788`), so the new close protection does not cover all outstanding requests. GBC queues stroke 2 correctly, but `GbcMapCanvas.tsx:726` checks only the map visit: both adjacent strokes have the same visit, so stroke 1 likewise clears busy while stroke 2 is beginning. Block new canvas strokes while finishing, or use a retained serialized chain plus outstanding-operation identity/count. Test delayed first end followed by immediate second click and X/Escape/Save.

3. **P2 — GBC incoming line endpoints stay stale after editing a destination.** `packages/ui/src/gbc/GbcWorldCanvas.tsx:622-627` invalidates only the saved map's cache. However `/api/warps/A` includes destination B's resolved `destEvent` (`packages/server/src/gbcRoutes.ts:263-266`), and A→B renders this embedded value (`GbcWorldCanvas.tsx:663-670`), never B's refreshed cache. Moving/deleting/reordering B's warp and saving refreshes B's outgoing data but leaves every cached incoming endpoint pointing at B's old coordinates/ordinal. Invalidate cached source payloads that can reference the saved map (or a suitably scoped full warp cache), and test saved destination changes with a different source map.

4. **P2 — an old GBC warp fetch can undo successful save invalidation.** `packages/ui/src/gbc/GbcWorldCanvas.tsx:635-643` installs payloads by name unconditionally. Save deletes that name and starts a new request, but an earlier request can resolve after the new response and replace it with pre-save data; an older rejection can delete the fresh entry too. Guard success and failure by request/cache-generation identity. GBA uses detached per-request entry objects, so an old completion does not overwrite its new cached entry; this finding is GBC-specific. Test both old-success-after-new-success and old-failure-after-new-success.

### Original finding resolution

- Pending mutation ownership: GBA now tracks the actual `useMapEditing` event and discard methods; popup undo/redo track completion and catch failures into the visible editing error. GBC popup session wraps move/add/delete/undo/redo/discard, with its existing editing workspace catching errors. The App counters and paint-busy ref jointly gate popup exit. Dirty destination switching waits for discard with a visible blocking overlay and rejects repeated entry/navigation. Canvas `editingDisabled` prevents starting a new operation while another operation or reload owns the popup.
- Paint completion: GBA `paintAt` now returns its promise instead of replacing the retained chain. Begin, each pencil/collision apply, and end append to the same chain; rectangle/shift await their apply before end without replacing the tail. The popup refuses another stroke while finishing. GBC retains its original main/context queue and applies finishing refusal only when the popup busy callback exists. Errors settle the busy guard and surface through the supplied callback.
- GBC incoming endpoint refresh: save clears cached source payloads, then refetches only currently relevant visible/scoped members. Cached A-to-B embedded destination coordinates are consequently refreshed when B is saved.
- GBC stale arrivals: both success and failure verify the per-map request identity, invalidated on save, before mutating cache or showing an error.
- Successful GBA save reload is tracked through completion and map-visit guarded. New canvas operations and popup close remain blocked while it loads. Same-map popup opening retains the App-owned dirty session.

### Remaining finding

**P2 — failed post-save GBA reload permits discard against the pre-save seed.** At `packages/ui/src/App.tsx:430`, the reload failure is caught and a visible warning is set, but `trackPopupOperation` releases busy. `useMapLayout.reload` leaves its previous payload unchanged on failure. `packages/ui/src/hooks/useEditSession.ts`'s discard callback (near lines 355–367) still restores `initialBlocks` and `initialMap`, sourced from that old payload. Concrete sequence: paint/event edit A, successfully save A, fail the ensuing reload with 500/network rejection, perform edit B, then Discard. The server returns to committed A, but the client restores the pre-A seed and calls it clean. The new warning honestly reports reload failure but does not prevent this state mismatch. Keep further editing blocked until the saved seed is recovered (with retry/reopen recovery), or update the seed from confirmed committed live state before relying on reload. Add a failed-reload regression followed by edit/discard. This is a source-proven failure path; no runtime reproduction is claimed.

Member filtering still restricts draw candidates and warp fetches; the server's placement inventory is broader, but outsiders are neither rendered nor fetched for lines. The anchored-first initial-fit limitation remains intentionally preserved.
